# 플레이테스트 에이전트

사람 대신 에이전트에게 게임을 끝까지 플레이시키고, 막히거나 어색한 지점을 보고받는 루프다.
에이전트는 코드를 고치지 않는다. 보고서를 받아 버그는 바로 고치고, 취향이 걸린 것은
주인에게 묻는다.

## 돌리는 법

1. `harness.mjs`가 프로토타입을 새 브라우저로 연다(Playwright 필요: `npm i -D playwright`).
2. 아래 두 브리핑 중 하나를 에이전트에게 준다. 둘은 서로 겹치지 않아서 동시에 돌려도 된다.
3. 보고서는 심각도(막힘/불편/다듬기)와 분류(버그/판단 필요)로 온다.

비용을 줄이려면 에이전트 모델을 한 단계 낮춘다. 1차는 가장 큰 모델로 돌렸고 두 에이전트가
합쳐 약 40만 토큰을 썼다. 스크린샷을 직접 보고 판단하는 일이라 토큰 대부분이 이미지다.

## 브리핑 A — 처음 켠 취준생

온보딩 → 홈 지도 → 말 걸 사람 찾기 → 퀘스트 하나(일부러 틀려 보기) → 옆 맵과 미니맵 이동 →
사건 한 편 → 보스 → 내 방 → 다른 탭들. 390×844와 360×640 두 크기. 코드를 읽지 않고
화면만 보고 다음에 뭘 할지 알 수 있는지를 본다.

## 브리핑 B — 중반 시스템

장비 조합과 지도 스프라이트 일치, 여러 칸 세간 배치(벽·문·붙박이 책상·다른 물건·내가 선 칸),
거처 올리고 내리기와 이사 정리, 방 안 동선, 라면, 새로고침 뒤 상태 복원, 미니맵 이동.
상태 세팅은 `page.evaluate`로 해도 되지만 그 뒤로는 사람처럼 누른다.

## 1차 결과 (2026-09-27)

두 에이전트가 찾은 것 중 버그 24건을 고쳤다(커밋 `d20f6f9`). 가장 컸던 셋:
실패한 퀘스트가 완료로 찍히던 것, 정답이 전부 첫 번째 보기였던 것, 방 안에서 이사하면
벽 속에 갇히던 것. 판단이 필요한 것은 따로 물었다.
