# 뉴비 퀘스트 CX 운영안

작성 기준: 2026-09-29 / 근거: 지난 플레이테스트(첫날 15~20분, 퀘스트당 1.5~2분, 새 문항 약 2주 소진), 코드의 ev() 목록 확인, 웹 자료 1건 직접 확인. 수치 중 "추정"은 검증된 벤치마크가 아니라 판단이다.

## 1. 첫 세션 이탈 위험 5곳

| # | 지점 | 위험 | 개선안 |
|---|---|---|---|
| 1 | 오락실 오프닝 + 첫 프롤로그 연속 재생 | 조작 없이 30초 이상 보면 "게임이 아닌가?"로 이탈. 무료 게임은 설치 직후 인내심이 가장 짧다 | 오프닝은 15초 이내 + 첫 탭부터 스킵 가능. 프롤로그는 60초 이내, 중간에 탭 1~2회 개입(대사 넘기기가 아닌 선택). 재실행 시 자동 스킵 |
| 2 | 온보딩 4단계(신분→거주→지역→아바타) | 대학생·취준생·직장인 모두 4단계. 지역·아바타는 "나중에 해도 되는" 입력 | 필수는 신분 1단계만. 지역·거주·아바타는 첫 퀘스트 보상 직후 "내 캐릭터 꾸미기"로 이연. 온보딩 총 소요 45초 목표 |
| 3 | 할배 튜토리얼 → 첫 보상까지 | 첫 경험치·코인이 늦으면 "지식 앱"으로만 인식. 목표: 앱 실행 후 90초 안에 첫 보상 | 튜토리얼 안에서 첫 퀘스트 1개(3문항)를 끝까지 하게 하고 종료 즉시 경험치·코인·스탯 변화 연출 |
| 4 | 동네 지도 첫 진입 | 건물·NPC가 많아 "어디로 가야 하나" 정체. 하루 3개 배정 개념을 모르면 방황 | 배정 퀘스트에 화살표·반짝임, 다 끝나면 "오늘 끝, 내일 3개 더"를 명확히 표시. 지도 위 무제한 탐색처럼 보이지 않게 |
| 5 | 첫날 15~20분 소진 후 종료 지점 | 첫날 다 쓰고 나면 다음 날 이유가 없다(가장 큰 D1 리스크) | 첫날 세션은 10~12분 안팎에서 "오늘의 3퀘스트 완료 → 내일 오는 이유(내일 보상·잠긴 건물·복습 알림)"로 의도적으로 닫는다. 남는 욕구는 방 꾸미기·거처 성장으로 돌린다 |

## 2. 잔존 목표와 장치

벤치마크
- 모바일 게임 전체(GameAnalytics, 2025 데이터, 16,000+ 게임): 중앙값 D1 약 22%, D7 4% 미만, D30 약 0.7~0.8%. 상위 25%는 D1 30% 초과, D7 6~7%, D30 1.6~1.8%. (출처: [GameAnalytics 2026 Benchmarks](https://www.gameanalytics.com/reports/2026-mobile-pc-gaming-benchmarks)) 장르별 값은 이 보고서에 없다.
- 교육 앱 벤치마크: 검색은 했으나 확인된 수치를 얻지 못했다. 아래 교육 앱 관련 수치는 모두 추정이다. 확인 대상: [Business of Apps 교육 앱 벤치마크](https://www.businessofapps.com/data/education-app-benchmarks/).

목표치 (추정: 상위 25% 이상을 겨냥. 출시 초기 표본이 작아 오차가 크다)

| 지표 | 최소선(추정) | 목표(추정) |
|---|---|---|
| D1 | 30% | 38% |
| D7 | 8% | 13% |
| D30 | 2.5% | 5% |

근거: 무료·보상형 광고 구조라 설치 유입이 넓고, 콘텐츠가 유한(2주 소진)해 D30는 콘텐츠 업데이트 없이는 게임 평균 수준으로 수렴할 가능성이 크다.

움직일 장치
- 알림 시각: 기본 저녁 8시(퇴근·귀가 후, 추정), 온보딩에서 묻지 말고 첫 출석 보상 수령 직후 권한 요청(notif_perm). 설정에서 시각 변경 가능. 시각별 알림 후 앱 진입률을 비교해 조정.
- 연속 보상: 스트릭 3·7·14·30일 마디에 큰 보상. 하루 놓쳐도 1회 복구권(광고 시청으로 복구 가능)으로 이탈 방지.
- 복습 알림: 간격 반복(1·3·7·14·30일)은 D1·D3·D7·D14·D30에 재방문 사유를 자연스럽게 만든다. "틀린 문항 N개 복습 대기" 문구.
- 콘텐츠 업데이트: 새 문항 소진(약 2주)을 기준으로 최소 2주마다 창구 문항 묶음 추가, 매주 1회 소규모(이벤트·계절 퀘스트) 추가. 최우선 순위.

## 3. 보상형 광고

원칙
1. 광고는 항상 선택. 강제 삽입·전면 광고 없음. 튜토리얼과 첫 3일은 광고 노출 자제.
2. 퀘스트·문항 풀이 중간에는 절대 띄우지 않는다. 결과 화면·상점·복구 시점에만 제안.
3. 광고를 보지 않아도 게임 진행이 막히지 않는다. 광고는 "가속"이지 "관문"이 아니다.
4. 시청 후 보상은 즉시·명확하게, 실패 시 재시도와 보상 보장.
5. 일 시청 상한을 두고, 광고 후 이탈률(다음 24시간 재방문)을 지표로 감시.

"보고 싶게" 만드는 보상 3가지
- 결과 화면 2배: 퀘스트 완료 직후 "경험치·코인 2배". 방금 얻은 보상의 확대라 손실감이 없다.
- 스트릭 복구권 / 욕구 회복: 하루 놓친 연속 기록을 살리거나 포만·체력 즉시 회복. 가장 손실 회피가 강한 지점.
- 방 꾸미기 한정 가구·복습 노트 힌트: 광고로만 얻는 가구(수집 욕구), 틀린 문항 해설 확장 열기. 한정 가구는 거처 성장과 연결해 목표를 만든다.

## 4. 측정 대시보드

꼭 볼 지표 8개
1. 설치→첫 퀘스트 완료율 (opening_start → onboard_done → quest_finish 첫 회)
2. 온보딩 단계별 이탈 (onboard_step의 i)
3. 첫 보상까지 시간 (opening_start~첫 quest_finish, 초)
4. D1·D7·D30 잔존 (app_open의 dayN)
5. 일 평균 퀘스트 완료 수와 세션 길이 (quest_finish, app_open 간 시간)
6. 출석·스트릭 분포 (daily_claim의 streak)
7. 알림 효율: notif_fire 후 24시간 내 app_open 비율, notif_perm 허용률
8. 광고 지표: 노출 대비 시청 완료율, 시청자 D7 vs 비시청자 D7, DAU당 광고 수

기존 이벤트 활용: opening_start, prologue, onboard_step/onboard_done, quest_start/finish/answer, daily_claim, day_start, app_open, notif_perm/notif_fire, boss_start, check_open/check_done, review_finish, tab_view, life_event, ending.

부족해서 추가 제안
- `opening_skip {t}`, `prologue_skip {t}`: 초 단위 스킵 시점
- `ad_offer {slot}`, `ad_start {slot}`, `ad_complete {slot,reward}`, `ad_fail {slot,err}`, `ad_close_early {slot}`
- `session_end {dur, quests}`: 앱 백그라운드 시
- `content_exhausted {building}`: 창구 문항이 다 떨어진 시점 (소진 지점 측정)
- `streak_break {len}`, `streak_restore {method}`
- `feedback_open`, `feedback_send {type}`, `error_report {code}` (아래 5번)
- 모든 이벤트에 `dayN`, 앱 버전, 콘텐츠 버전 공통 속성 부여

## 5. 인앱 피드백·오류 신고

- 진입점: 설정 하단 "문의·신고" 하나, 퀘스트 결과 화면의 문항별 "이 문항 신고" 작은 버튼. 화면 상시 버튼은 두지 않는다.
- 문항 신고 = 가장 중요. 사회초년생 정보(세금·계약·보험 등)는 틀리면 신뢰가 무너진다. 사유 4택(틀린 정보, 오래된 정보, 이해 어려움, 오탈자) + 선택 메모. 문항 ID·콘텐츠 버전 자동 첨부.
- 오류 신고: 앱 버전, 기기·OS, 최근 이벤트 20개, 저장 데이터 요약을 자동 첨부. 사용자는 한 줄 설명만 쓴다. 이메일 앱을 열지 않고 앱 안에서 전송.
- 만족도: 퀘스트 10회 완료 시점 1회만 별점(1~5) + 자유 의견. 4점 이하면 사유 선택. 스토어 리뷰 유도는 5점일 때만.
- 응답: 접수 확인 문구 즉시, 문항 오류는 다음 콘텐츠 업데이트에 반영 후 "제보 반영" 표시(제보 보상 소량 코인).
- 운영: 주 2회 확인. 같은 문항 신고 3건 이상이면 우선 검수.

## 6. 출시 후 2주 운영 기준

표본이 작으면(일 설치 100 미만) 비율 판단을 미루고 개별 세션 기록(질적)을 우선한다. 아래 기준은 추정 기반 기준선이다.

| 주차 | 볼 것 | 기준 → 조치 |
|---|---|---|
| 1주 | 온보딩 완료율, 첫 보상까지 시간 | 온보딩 완료율 80% 미만 → 단계 축소(신분만 필수). 첫 보상 120초 초과 → 프롤로그 단축·튜토리얼 퀘스트 앞당김 |
| 1주 | D1 | 30% 미만 → 첫날 종료 설계(내일 이유)·알림 시각·첫날 길이 점검. 30~38%는 관찰 |
| 1주 | 오류·크래시, 문항 신고 | 오류 사용자 2% 초과 → 기능 개발 중단 후 수정. 문항 신고 3건 → 즉시 수정 |
| 2주 | D7, 스트릭 3일 이상 비율 | D7 8% 미만 → 복습 알림·스트릭 보상 강화, 3일차 이탈 원인 확인 |
| 2주 | 콘텐츠 소진 (content_exhausted) | 소진 사용자 20% 초과 → 문항 묶음 조기 추가(2주 주기를 10일로) |
| 2주 | 광고 시청 완료율·시청자 D7 | 시청자 D7이 비시청자보다 낮음 → 노출 위치·빈도 하향. 시청률 낮음 → 보상 문구·배치 개선 |

우선순위 판단 순서: 오류 → 온보딩·첫 보상 → D1 → 콘텐츠 소진 → 광고 최적화. 광고 수익은 재방문이 확보된 뒤에 튜닝한다.

## 확인 필요 사항
- 교육 앱 D1·D7·D30 실측 벤치마크(위 목표는 추정)
- 광고 SDK 연동 상태(코드에서 광고 이벤트는 확인되지 않았다)
- 한국 사회초년생 대상 알림 시간대 데이터(저녁 8시는 가설)
