# 뉴비 퀘스트

대학생·취준생·사회초년생이 실제로 손해 보는 지점만 골라 배우는 도트 RPG.
월세 계약, 전세사기, 주휴수당, 4대보험처럼 어려워 보이는 제도를 **의·식·주·금·직** 다섯 테마로 나눠
퀘스트로 푼다. 캐릭터는 배운 만큼 성장하고, 거처는 노숙에서 시작해 한 단계씩 올라간다.

게임 본체는 `prototype/newbie-quest-demo.html` 한 파일이다. 안드로이드 앱은 Expo(React Native) 셸이 이 HTML을 웹뷰로 열고, 광고·뒤로가기·공유·외부 링크만 네이티브로 처리한다.

## 폰에서 앱처럼 열기

`docs/`는 프로토타입을 GitHub Pages로 여는 폴더다. 저장소 Settings → Pages에서
Branch를 `main`, 폴더를 `/docs`로 두면 `https://ksy93-spec.github.io/Newbie-Game/`에 뜬다.
폰 브라우저로 열고 "홈 화면에 추가"를 하면 주소창 없이 전체 화면으로 열린다.
프로토타입을 고친 뒤에는 `node tools/pages/build.mjs`로 `docs/`를 다시 만든다.

## Android 앱 빌드

구조: `App.tsx`가 `src/GameShell.tsx`를 띄우고, 웹뷰가 게임 HTML을 `https://newbie-quest.app/` 주소(가짜 origin, 네트워크 요청 없음)로 연다.
`src/bridge/`가 저장 백업(`nq.v8` → AsyncStorage), 보상형 광고, 뒤로가기, 외부 링크, 공유를 맡는다.

PC에 Node가 없어도 빌드할 수 있다. GitHub Actions의 "Android build" 워크플로가 EAS 클라우드에 빌드를 맡긴다.
저장소 시크릿 `EXPO_TOKEN`(expo.dev > Account settings > Access tokens)이 있어야 하고, Actions 탭에서 Run workflow를 누르거나 `android-preview-*` 태그(폰 설치용 APK), `android-release-*` 태그(스토어용 AAB)를 푸시하면 돈다. 결과 파일 링크는 실행 요약에 나온다.
게임 HTML은 앱을 위해 고치지 않는다. 필요한 연결은 `src/bridge/injected.mjs`가 웹뷰에 주입한다.

```bash
npm install
npm run build:game     # prototype HTML -> src/game/gameHtml.ts (저장소에는 없는 생성 파일)
npm run typecheck      # tsc --noEmit
npm test               # 브릿지(Playwright)·광고 상태 기계 테스트. 크로미움 필요
npm run export:android # 번들이 만들어지는지만 확인(빌드 아님)
```

- `build:game`은 `start`, `android`, `typecheck`, EAS 빌드(`eas-build-pre-install`) 앞에서 자동으로 돈다. 게임 HTML을 고쳤으면 다시 돌린다.
- 광고 SDK는 네이티브 모듈이라 Expo Go에서 안 돈다. 개발 빌드나 APK로 확인한다.

EAS 빌드(처음 한 번 `eas init`으로 `app.json`의 `extra.eas.projectId`를 채운다):

```bash
npx eas build --profile preview --platform android      # APK, 내부 배포
npx eas build --profile production --platform android   # AAB, 플레이 스토어 제출용
```

`development` 프로파일은 개발 클라이언트가 필요하다. 쓰려면 `npx expo install expo-dev-client`를 먼저 한다.

테스트 광고에서 실제 광고로 바꾸는 곳(출시 전에 사람이 한다):

1. AdMob 콘솔에서 앱과 보상형 광고 단위를 만든다.
2. `src/config/ads.ts`: `REAL_REWARDED_UNIT_ID`에 광고 단위 ID를 넣고 `USE_TEST_ADS`를 `false`로 바꾼다.
3. `app.json`: `react-native-google-mobile-ads` 플러그인의 `androidAppId`를 실제 앱 ID로 바꾼다. 지금 값은 구글 공개 테스트 앱 ID다.
4. 동의창(UMP)은 AdMob 콘솔의 개인정보 및 메시지에서 메시지를 만든 뒤에 나온다. 창을 미리 보려면 `UMP_DEBUG_EEA`를 잠시 `true`로 둔다. 출시 빌드에서는 `false`.

## 구조 (예전 RN 버전, 참고용)

```
src/
  core/     순수 로직. React도 RN도 모른다. 테스트가 여기에 붙는다.
    day.ts          KST 달력일. 어제와 오늘을 구분하는 기준
    state.ts        저장 상태와 마이그레이션
    daily.ts        출석·연속·오늘의 퀘스트 세 개
    review.ts       틀린 문항 간격 반복(1·3·7·14·30일)
    curate.ts       프로필에 맞는 퀘스트 고르기
    progress.ts     퀘스트·보스 결과 반영
    combat.ts       보스 피해 계산
    events.ts       계측 이벤트 이름과 수집
    pack-loader.ts  문항 묶음 갱신(EAS Update / 원격 JSON)
  data/     문항·아이템·거처·테마. 사람이 읽고 고치는 자리
  sprite/   레이어 아바타. Skia로 합성하고 색을 갈아 끼운다
  screens/  화면
  ui/       도트 UI 조각과 촉각·소리
  store/    zustand + AsyncStorage
```

### 왜 이렇게 나눴나

**`core/`에 React를 넣지 않는다.** 하루 루프와 복습 간격은 날짜를 밀어 가며 검증해야 하는데,
순수 함수로 두면 `node --test`로 바로 돌릴 수 있다. 화면을 띄우지 않고 "사흘 건너뛰면 연속이 끊긴다"를
확인할 수 있어야 이 게임의 뼈대가 무너지지 않는다.

**문항을 앱에 박아 두지 않는다.** 최저임금이 바뀌면 문항 하나를 고치려고 스토어 심사를 다시 받게 된다.
`data/pack.ts`는 내장 폴백일 뿐이고, 실제 갱신은 EAS Update로 같은 모양의 JSON을 내려받아 덮어쓴다.
내려받은 묶음은 `validatePack()`을 통과해야 적용되고, 실패하면 조용히 내장으로 돌아간다.

**문항마다 확인처와 기준일을 단다.** 전세사기·청약·4대보험은 틀리면 실제 금전 피해로 이어진다.
해설 아래에 고용노동부·한국장학재단·국민건강보험공단 같은 원문 링크와 기준일을 띄우고,
"법률·세무 자문이 아니라 정보 제공"임을 명시한다.

**계측 이름을 먼저 확정했다.** 어디서 이탈하는지 모르면 무엇을 고칠지도 모른다.
호출 지점은 이미 전부 박혀 있고 `setSink()`에 SDK를 꽂으면 그대로 흘러간다.

## 아바타가 레이어인 이유

손으로 그린 원본 한 장으로는 옷을 갈아입힐 수 없고, 코드로 생성한 도트는 손그림 품질을 못 따라간다.
그래서 원본을 **몸 · 하의 · 상의 · 손 · 머리카락** 다섯 장으로 쪼갰다.
각 장이 자기 옷감만 담고 있으므로 색을 바꾸면 반드시 눈에 보인다.

색 교체는 밝기비를 유지한다. 원본 옷감의 밝기를 1로 두고 픽셀마다 비율을 계산해 새 색에 곱하면
손으로 찍은 명암이 그대로 살아난다. 밝기 26 미만(검은 외곽선)은 건드리지 않아야 도트가 뭉개지지 않는다.

확대는 `FilterMode.Nearest`로 정수 배율만 쓴다. 1.5배 같은 건 도트를 무너뜨린다.

스프라이트를 다시 만들려면 `tools/`의 추출 스크립트를 참고한다.
원본 → 레이어 분리 → 소품 제거 → 왼팔 복원 → 다리 골 파기 순서로 돈다.

### 대학생 아바타

원화가 손을 모으고 가방을 멘 자세라 옛 아바타와 리그가 다르다. 소품을 지울 일이 없으니
hand 레이어가 없고, 색을 바꿔야 하는 건 머리 · 상의 · 하의 셋뿐이라 나머지는 전부 body에 둔다.
가방은 재킷과 같은 남색이어서 색으로는 못 가른다. 자리로 가른다. 가방이 body에 있으므로
상의를 갈아입어도 가방 색은 그대로다. 옷이 아니니 변하면 안 된다.

줄일 때는 평균이 아니라 최빈값을 쓴다. 677px 원화를 BOX로 평균 내면 재킷과 셔츠 경계가 섞여
색이 스무 개로 번지고, 그러면 레이어를 색으로 가를 수가 없다. 블록마다 가장 많은 색을 고르면
평평한 면과 단단한 경계가 그대로 남는다.

### 조연

NPC 넷(할아버지 · 할머니 · 남자아이 · 여자아이)과 펫 셋(강아지 · 거북 · 참새)은 갈아입을 일이
없으므로 한 장짜리 그림으로 둔다. `sprite/cast.ts`가 크기와 배역표를 들고 있고,
말 거는 사람 이름이 표에 없으면 이름을 해시해 늘 같은 얼굴이 나오게 한다.

한 장에 일곱을 그린 원화에서 잘라내는 일이 까다로웠다. 배경이 밝은 벽과 어두운 건물 두 가지라
한 가지 방법으로는 안 된다. 외곽선 바깥을 테두리에서 채우는 방법은 할머니의 흰머리를 지키지만
어두운 건물을 남기고, 같은 색을 따라가며 지우는 방법은 건물을 떼어내지만 흰머리를 먹는다.
그래서 둘을 교차시키고, 인물을 감싼 건물 조각은 색으로 한 번 더 지운다.
잘라낼 상자는 인물보다 넉넉하게 잡아야 한다. 상자가 인물을 스치면 그 변에서 시작한 채우기가
몸 안으로 흘러들어 할아버지의 지팡이나 남자아이의 종이비행기가 통째로 사라진다.

### 지도

홈은 원래 대시보드였다. 오늘 할 일 세 개가 카드로 쌓여 있고 캐릭터는 그 위에서
제자리걸음을 했다. 그래서 한 번은 옆에서 보는 거리로 바꿨는데, 두 가지가 걸렸다.
사람을 한 줄로만 세울 수 있어 다섯 명만 돼도 겹쳤고, 구역 폭을 사람 수로 정하다 보니
세계 좌표가 상황에 따라 움직여서 걷다가 제자리로 튀는 일까지 생겼다.

지금은 위에서 내려다보는 타일 맵이다. 좌표가 고정된 격자라 튈 곳이 없고, 사람을
가로세로로 흩어 세울 수 있고, 문으로 맵을 나눌 수 있다. 16px 타일에 화면은 11×15칸이고,
바깥 맵은 22×15칸이다.

홈에서 제일 오래 보는 것이 지도라서 화면의 대부분을 준다. 스탯 막대와 프로필 카드는
걷어냈다(스탯은 캐릭터·도감 탭에 그대로 있다). 남은 것은 출석 버튼과 "오늘 몫" 한 줄뿐이다.
화면 높이가 작으면 지도 쪽이 먼저 줄어들어, 어떤 폰에서도 탭바까지 한 화면에 들어간다.

| 맵 | 여기 있는 것 |
| --- | --- |
| 내 방 | 복습 노트(책상) · 문으로 동네 |
| 1 동네 | 부동산 사장 · 주민센터 직원 · 게시판(전세 계약 하루) · 우리 집 문 |
| 2 학교 앞 | 동기 · 선배 · 자취 선배 · 알바 선배 · 장학팀 · 게시판(첫 알바 한 달) |
| 3 고용센터 앞 | 고용센터 상담원 · 공단 상담원 · 게시판(면접 다니는 달) |
| 4 회사 앞 | 인사팀 · 3년차 선배 · 게시판(첫 월급 세 달) |
| 5 은행 골목 | 은행 창구 직원 · 세탁소 사장 · 보스 셋 |

왼쪽에서 오른쪽으로 갈수록 나중에 겪을 일이 나온다. 맵의 가장자리를 밟으면 다음 맵이고,
문을 밟으면 안으로 들어간다. 걸어가는 것이 곧 시간이 흐르는 것이다.

조작은 셋이다. 타일을 누르면 너비 우선으로 길을 찾아 걸어가고, 사람을 누르면 그 옆까지
가서 말을 건다. 방향 패드를 누르고 있으면 계속 걷는다. 키보드 방향키와 스페이스도 같이 받는다.

A 버튼이 있었는데 걷어냈다. 사람을 직접 누르면 되니까 쓸 일이 없었다. 그 자리에는 미니맵을
뒀다. 지금 맵에서 내가 어디 있고 누가 남았는지가 보이고, 누르면 전체 지도가 열려서 다른 맵으로
바로 건너뛴다. 옆으로만 걸어서 다섯 맵을 오가는 건 길다.

말을 걸 수 있는 사람 위에는 누르라는 손짓이 뜬다. 위아래로 조금 흔들려야 눈에 들어온다.
노랑이면 오늘 몫, 흰색이면 아직 안 푼 것이고, 발밑에 같은 색 고리가 생긴다. 이미 끝낸 사람은
머리 옆에 회색 체크가 붙어서 조용히 서 있는다.

옆모습 종이인형은 위에서 못 쓴다. 그렇다고 손그림 NPC를 네 방향으로 다시 그릴 수도 없다.
그래서 지도에 서는 몸은 절차로 만든다(`personTopG`). 손그림은 대화와 전투 화면에 그대로
남는다. 필드 스프라이트와 전투 스프라이트를 따로 쓰는 그 구조다.

처음에는 색만 물려받게 했더니 다들 같은 사람이었다. 18×26칸 안에서도 무엇을 들었는지
무엇을 썼는지는 보여야 한다. 안 그러면 옷을 사는 이유가 없어진다. 지금은 이만큼 반영한다.

| 내 캐릭터 | NPC |
| --- | --- |
| 무기(볼펜·마우스·텀블러·키보드·결재판·노트북·법인카드)를 손에 든다 | 머리 모양 다섯(단발·장발·웨이브·번·대머리) |
| 탈것 셋(킥보드·자전거·경차)을 타고 다닌다 | |
| 안경 · 비니 · 넥타이 머리띠 | 안경 · 선글라스 · 모자 |
| 후드 · 사원증 · 금장 라펠 · 롱패딩(몸이 한 뼘 넓어진다) | 넥타이 · 앞치마 · 명찰 |
| 트레이닝복 옆선 | 소품(지팡이 · 가방 · 서류판 · 서류철) |
| 아바타 성별에 따라 머리 길이 | |

머리카락이 눈까지 덮으면 다들 같은 사람이 된다. 이마를 남겨 두는 것만으로 꽤 달라졌다.
내 캐릭터는 발밑의 흰 표시로 찾는다.

옆모습은 앞모습에서 눈 하나를 지운 것이었다. 그건 옆모습이 아니다. 오른쪽 보기를 따로
그리고 왼쪽은 뒤집어 쓴다. 몸을 좁히고, 팔은 앞의 하나만 보이고, 코가 앞으로 나오고,
뒤통수에 머리가 남고, 다리는 앞뒤로 엇갈린다.

탈것은 두 겹으로 그린다. 몸 뒤에 깔리는 것(바퀴·프레임)과 몸 앞에 오는 것(핸들·계기판).
한 겹으로 그리면 아래를 볼 때 사람이 탈것을 통째로 가려서 뭘 탔는지 안 보인다.
경차는 지붕을 덮으면 사람이 사라져서, 위가 열린 차로 그리고 상체만 앉혔다.
방 안에서는 내린다.

## 내 방과 세간

거처가 곧 방이다. 이름만 바뀌는 것보다 걸어 다닐 수 있는 칸수가 달라지는 편이 낫다.

| 거처 | 방 |
| --- | --- |
| 노숙 | 들어갈 방이 없다. 문을 밟으면 그렇게 말한다 |
| 움막 · 텐트 | 7×6 · 8×6, 바닥에 돗자리 |
| 찜질방 | 8×6 골방 하나 |
| 고시원 | 6×7. 좁고 길다 |
| 반지하 → 원룸 전세 | 10×7 → 12×8 |
| 투룸 전세 | 14×9, 가운데 벽이 서고 방이 둘이 된다 |
| 내 집 | 16×10 |

방이 생겼으니 채울 것도 필요하다. 물건마다 놓을 수 있는 최소 거처와 차지하는 칸이 있다.
고시원 골방에 3칸짜리 소파를 넣을 수는 없다.

| 물건 | 칸 | 최소 거처 | 값 |
| --- | --- | --- | --- |
| 라면 5봉지 | — | 노숙 | ￦60 |
| 접이식 매트 | 2×2 | 움막 | ￦90 |
| 선풍기 | 1×1 | 찜질방 | ￦140 |
| 접이식 책상 | 2×1 | 고시원 | ￦200 |
| 소형 냉장고 | 1×2 | 반지하 | ￦300 |
| 접이식 침대 | 2×2 | 반지하 | ￦340 |
| 세탁기 | 1×1 | 원룸 월세 | ￦420 |
| 바퀴 달린 TV | 2×1 | 원룸 전세 | ￦560 |
| 옷 관리기 | 1×2 | 투룸 전세 | ￦760 |
| 2인용 소파 | 3×1 | 투룸 전세 | ￦980 |

이사하면 방 모양이 통째로 바뀐다. 자리가 안 맞는 물건은 창고로 가고, 홈에 "이사했습니다 ·
세간 정리하기"가 뜬다. 누르면 가진 물건을 하나씩 다시 놓는다. 자동으로 벽에 붙여 버리면
이사한 느낌이 안 난다.

사면 벽을 따라 저절로 놓이던 것을 걷어냈다. 내 방인데 내가 못 고르면 내 방이 아니다.
구매를 누르면 방으로 들어가 배치 화면이 열린다. 타일을 누르거나 방향 패드로 유령을 옮기고,
들어가는 자리면 초록 테두리, 안 되면 빨강이다. 이미 산 물건은 상점에서 다시 눌러 옮긴다.

붙박이 책상(복습 노트)이 차지한 칸에는 아무것도 못 놓는다. 소파로 덮어 버리면 노트가 사라진다.
세간은 공격과 방어에 그대로 더해지고, 물건 위로는 걸어 다닐 수 없다. 라면은 퀘스트에서
목숨 하나를 되살린다. 쓸 자리를 만들어 두지 않으면 산 의미가 없다.

시연이라 여섯 맵이 처음부터 다 열려 있다. 실제 앱에서는 신분과 스탯으로 잠가서,
갈 수 있는 맵이 늘어나는 것 자체가 진행이 되게 할 생각이다.

## 거처

열 단계인데 여섯 개가 같은 건물에 색만 달랐다. 거처는 이 게임의 유일한 보상 트랙이라,
올라가도 같은 그림이면 올린 이유가 없다. 색이 아니라 실루엣부터 다르게 다시 그렸다.

상자 → 움막 → 텐트 → 낮고 넓은 찜질방 → 좁고 높은 고시원 → 땅 밑으로 꺼진 반지하 →
계단이 밖에 붙은 다세대 → 벽돌 다세대 → 발코니가 생긴 투룸 → 지붕과 마당이 있는 집.
멀리서 실루엣만 봐도 어디 사는지 알아야 한다.

그림은 프로토타입의 `houseG()`가 그리고, 앱에는 그 결과를 PNG로 구워서 넣는다
(`tools/export-houses.md`). 같은 그림을 두 번 그리면 언젠가 갈라진다.
